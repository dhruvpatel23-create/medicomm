01 · Executive brief

MediComm in one page

MediComm is a focused digital workspace for medical students preparing for high-stakes exams. It combines question-led learning with performance feedback, peer communities, rankings, and short competitive battles.

“Practice the right medical questions, understand weak areas, and keep momentum—inside one connected learning workspace.”
19medical subjects in the official catalogue
15exam-year collections represented
13,035distinct question records served after de-duplication
10main product destinations

The problem

  • Exam preparation is fragmented across question banks, notes, analytics, chats, and peer groups.
  • Students often know their score but not what to study next.
  • Consistency is hard when feedback loops are slow and solitary.

The product answer

  • Structured PYQ, AI-supplemental, and USMLE-style practice.
  • Confidence, accuracy, pacing, flags, and weak-topic signals.
  • Community, direct messages, leaderboards, and 1v1 duels.
Pitch discipline: these figures describe the current repository and runtime inventory—not verified active users, revenue, or clinical outcomes.

05 · Learning intelligence

How attempts become useful feedback

Capturesubject, topic, correct/incorrect, duration, activity, timestamp
→
Aggregateperiod, subject, day, activity type
→
Explainaccuracy, pace, trend, mastery, attention list

Analytics currently computed

  • Accuracy over 30 / 90 / 365 days
  • Questions solved
  • Average time per question
  • Total measured study time
  • Daily accuracy trend
  • Subject mastery
  • Time by PYQ / revision / battle
  • Top weak topics from incorrect answers

Important implementation fact

Detailed analytics events and practice progress are stored in browser localStorage, scoped to the current user identifier and capped at the most recent 2,000 events.

Meaning: it works well for a prototype and a single device, but full cross-device learning history requires moving event storage to the server/database.

09 · Backend & API

The application server

The backend is a single Node.js 22 service built with the native HTTP module—no Express framework. It serves the compiled website, JSON endpoints, and uploaded files.

Identity

Signup, login, session validation, logout, profile updates, public profiles, and user search.

Learning

Practice library, filterable questions, AI generation, profile statistics, platform summary, leaderboard.

Network

Communities, membership, threads, images, direct conversations, rated queue, duel completion.

Request pattern

Client requestJSON + optional Bearer token
→
Route handlerparse + validate + authorize
→
Read / mutatein-process state snapshot
→
Persistlocal JSON then Supabase write chain

Useful implementation choices

  • Server-generated random IDs and session tokens
  • Timing-safe password comparison
  • Output sanitizers for public/private data
  • Deterministic seeded duel question selection
  • Immutable caching for built assets
  • Local fallback if Supabase is unavailable

Scale limitations

  • Whole application state is cloned and rewritten
  • Writes are serialized in one process
  • No transactional relational model
  • Polling rather than realtime subscriptions
  • No automated API test suite in package scripts
  • Single server file is approximately 2,270 lines

11 · AI pipeline

Where artificial intelligence is used

AI is an optional content-generation path for supplemental practice. The configured default model is Gemini 2.5 Flash; the app can also run without an AI key.

Topic requestsubject + learning intent
→
Gemini APIstructured JSON schema
→
Server validatorfour options + answer + explanation + subject
→
AI banksource explicitly tagged “ai”

Guardrails already in code

  • JSON response schema
  • Exactly four options
  • Answer index restricted to 0–3
  • Answer must equal the indexed option
  • Non-empty prompt and explanation
  • Subject must exist in catalogue
  • Separate AI source label

Guardrails still needed

  • Medical editorial review and audit trail
  • Reference/citation requirements
  • Duplicate and leakage detection
  • Bias, ambiguity, and factual-quality scoring
  • Versioning when source guidelines change
  • Cost limits, abuse controls, and monitoring

Pitch-safe wording

“AI expands targeted practice, while deterministic validation and a future clinician-review workflow protect quality. AI questions are labeled separately from source-tagged PYQs.”

Avoid saying: “Every question is medically verified” unless the business can provide reviewer identity, process, and evidence for the current inventory.

12 · Security, privacy & trust

Current controls and honest gaps

Implemented controls

  • Passwords salted and hashed with PBKDF2-SHA512
  • Timing-safe hash comparison
  • Random bearer-session tokens
  • Public-user response sanitization
  • Profile image size boundary
  • Path basename handling for served uploads
  • Supabase service key kept server-side
  • Row-level security on the state table

Before production scale

  • Restrict permissive CORS
  • Add rate limits and brute-force protection
  • Add email verification and password recovery
  • Prefer secure HttpOnly session cookies
  • Add CSRF strategy if cookies are adopted
  • Validate image MIME and scan uploads
  • Add security headers and audit logs
  • Move secrets to managed deployment storage

Data classification

ClassExamplesRecommended treatment
Account dataName, email, phone, medical collegeConsent, encryption in transit/at rest, deletion flow, strict access.
Learning dataAttempts, mistakes, pace, weak topicsTreat as private profile data; clear retention and export rules.
Social contentThreads, replies, images, messagesModeration, reporting, block tools, retention and takedown process.
PaymentsPlan, order, entitlement, provider statusUse provider-hosted checkout; never store raw card/UPI credentials.
Positioning boundary: this is an exam-preparation product, not a diagnostic or clinical decision-support system. Terms, disclaimers, and content governance should make that explicit.

Highest-priority risks

Content provenance

Confirm rights, source traceability, labeling, and expert review for every claim-worthy content set.

Data architecture

Replace one-row snapshot storage before meaningful concurrency and analytics volume.

Security & moderation

Harden identity, uploads, community safety, logging, and incident response.

Market validation

Prove repeated use and willingness to pay; repository scale is not product-market fit.

Recommended investor ask framing: fund the transition from feature-complete MVP to evidence-backed learning product—quality assurance, learner instrumentation, production data architecture, and a measured paid pilot.
